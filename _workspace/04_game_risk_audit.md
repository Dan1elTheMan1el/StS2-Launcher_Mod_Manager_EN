# 04 · 게임-측 세이브 위험요소 감사 (Risk Register)

**작성:** sts2-game-specialist · **모드:** 감사 전용(코드/빌드/커밋 없음) · **폰 미연결(adb 불가)**
**대상 빌드:** 게임 `sts2.dll` v0.108.0(PC 설치본) + ≤v0.107 참조본(arm64) · 런처 브랜치 `fix/issue-55-v0108-save-path-compat`
**방법:** `ilspycmd` 전체 디컴파일 + 런처 소스 대조. 게임 동작은 추측 없이 디컴파일로 확인.

## 0. 부팅·동기화 흐름 요약 (레지스터 해석용 필수 맥락)

게임 측 세이브 계층(디컴파일 확인):

- **세이브 파일 전수** (게임이 쓰는 것 전부):
  - 계정 스코프(프로필 밖): `profile.save`(`ProfileSaveManager.ProfilePath`, LastProfileId 만 담음), `settings.save`(기기 전용, **클라우드 동기화 금지** — 게임이 `DeleteSettingsFromCloud` 로 매 sync 시 클라우드에서 삭제)
  - 프로필 스코프(`user://{platform}/{uid}/{modded?}/profile{N}/saves/`): `progress.save`, `prefs.save`, `current_run.save`, `current_run_mp.save`, `history/*.run`
  - `leaderboards.save` — Steam 리더보드 로컬 캐시. `EnumerateCloudSyncTasks` 에 없음 → **클라우드 동기화 대상 아님**(모바일선 Steam 리더보드 없어 사실상 inert).
- **게임 클라우드 결정**: `NGame.GameStartup` → `DoCloudSync()`(디컴 line 56558) → `SaveManager.ShouldOverwriteCloudWithLocal()` 가 true 면 `OverwriteCloudWithLocal()`(로컬→클라우드 무조건 덮어쓰기), false 면 `SyncCloudToLocal()`(클라우드→로컬).
- **모바일 핵심 특이점**: `GameStartup` 은 `DoCloudSync` 를 기다리는 루프에서 `if (!SteamInitializer.Initialized) break;`(line 56517-56525) 한다. 모바일은 Steam SDK 없어 `SteamInitializer.Initialized == false` → **게임은 자기 클라우드 sync 를 사실상 기다리지 않고 즉시** `InitProfileId()`/`InitProgressData()` 로 넘어간다. 실제 동기화는 런처의 pre-PLAY 핸드셰이크(`RunLauncherThenGame`)가 담당.
- **런처가 게임 세이브 경로에 개입하는 지점**: `NGame.GameStartupWrapper`(교체), `SaveManager.ConstructDefault`(클라우드 래핑 주입), `CloudSaveStore.SyncCloudToLocal(path)`(per-file → `AutoSyncFileAsync`). **패치 안 함**: `DoCloudSync`, `SaveManager.SyncCloudToLocal()`(orchestrator), `ShouldOverwriteCloudWithLocal`, `OverwriteCloudWithLocal`.
- **저장 경로**: 모든 게임 세이브는 `SaveManager._saveStore` = 게임 `CloudSaveStore`(로컬+클라우드) → `CloudStore.WriteFile` = 런처 `SteamKit2CloudSaveStore.WriteFile`. 여기서만 GuardB(빈 쓰기)·GuardC(깨진 JSON) 방어가 작동. **둘 다 "유효한 비어있지 않은 JSON" 은 통과시킨다.**

## 2. 상위 5개 위험 (요약)

1. **G1a/G1b — 버전 다운그레이드 lossy/파국 재저장 (최우선).** 상위버전 progress 를 하위버전 빌드가 열면 `MigrationManager` 가 신규 필드 폐기(scavenge 성공=lossy) 또는 기본값 생성(scavenge 실패=커리어 전체 소실) 하고, **다음 저장이 그 결과를 클라우드에 밀어넣는다.** GuardB/GuardC 는 "유효 비어있지않은 JSON" 이라 못 막는다. 다만 **내용(카드/유물 등 ModelId 키)은 `ProgressState` 의 unknown-버킷이 보존**하므로 실손실은 신규 스키마 필드에 국한(정확 범위는 v22 베타 빌드 부재로 미확정). **권고: progress.save 클라우드 push 결정부에 schema_version 다운그레이드 게이트 추가**(로컬 < 클라우드면 차단+다이얼로그).

2. **G7 — 인세션 업데이트/AtlasWipe 재시작이 cloud flush 우회.** `restartApp` 직접 호출이 `QuitPrefix` 의 `Flush(300s)` 를 안 거쳐 큐잉 업로드 유실 → 클라우드가 다음 실행까지 stale, 그 사이 타 기기가 옛 데이터 봄. **권고: 두 `restartApp` 앞에 `Flush` 추가.** (순수 런처 변경, 빌드로 검증 가능)

3. **G4 — UnifiedSavePath 등 GetProfileDir 재작성 모드 vs 런처 이중 레이아웃 가정.** 경로 통합 모드가 한 기기에만 걸리면 modded 진행도가 unmodded 프로필 키로 클라우드에 올라 상대 기기 오염 가능. **실측 유령 unmodded profile2 슬롯의 유력 후보(미확정).** 구조적 fix 곤란 → **운영 안내**(양 기기 동일 모드/경로).

4. **G8 — settings.save 클라우드 혼입.** 런처가 SaveManager 를 단일인자로 만들어 기기전용 settings 가 클라우드로 감(게임 PC 는 local-only). 게임 삭제 로직이 대개 정리하나 정합성 이탈. **권고: 2-인자 생성자로 정합화**(안전·저비용).

5. **G2 — ShouldOverwriteCloudWithLocal 함정.** 현행 `HasUserEnabledCloudSync()=>true` 는 **정답**(false 면 blind local→cloud push). 잔여 위험은 "빈 목록을 loaded 로 신뢰하는" 캐시 freshness 뿐 → steam-측 CloudFileCache 감사와 공유.

**참고 — 반증된 가설**: **G3(BaseLib 동적 ModelId 해시)는 세이브를 위협하지 않음.** `ModelId` 는 문자열 `"CATEGORY.ENTRY"` 로 직렬화되어 런타임 해시 변동과 무관하고, 미등록 키는 unknown-버킷으로 보존·재emit 된다. `Unknown card ID` 경고는 무해. 런처 방어 불필요.
